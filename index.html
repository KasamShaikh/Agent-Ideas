01

Understand what you are building

This is one hosted application containing four agents. Each agent receives the previous agent's output, so the order matters.

Resume ParserStructures the resume and carries the full job description forward.
JD AnalystExtracts required and preferred skills and carries the resume forward.
Matching AgentCompares both profiles and calculates a score out of 100.
Gap AnalyzerBuilds the roadmap and finds Microsoft Learn resources through MCP.

The repository already contains the complete working code. For a two-hour beginner session, use the reference implementation directly instead of rebuilding all four prompts.

02

Install and check the required tools

Complete these checks before starting the two-hour build timer.

  • Latest Visual Studio Code
  • Git
  • Python 3.13 recommended
  • Azure CLI 2.80 or later
  • Foundry Toolkit for VS Code
  • Python extension for VS Code

Install the extensions

  1. Open VS Code and press Ctrl+Shift+X.
  2. Install Foundry Toolkit for VS Code by Microsoft.
  3. Install Python by Microsoft.
  4. Run Developer: Reload Window from the Command Palette.

Verify in a new PowerShell terminal

git --version
python --version
az --version

Stop and fix any command that is not recognized. On Windows, reinstall Python with Add Python to PATH selected.

03

Clone the repo and open the ready solution

Use the completed Lab 02 implementation so your time is spent learning and deploying the workflow.

git clone https://github.com/microsoft-foundry/Foundry_Toolkit_for_VSCode_Lab.git
cd Foundry_Toolkit_for_VSCode_Lab\workshop\lab02-multi-agent\PersonalCareerCopilot
code .

A new VS Code window should open with main.py, agent.yaml, Dockerfile, and requirements.txt at the root.

Important: Open the PersonalCareerCopilot folder itself. Otherwise the included F5 and task configurations may not be found.
04

Sign in and choose the Azure subscription

The code uses Microsoft Entra authentication through DefaultAzureCredential. No API key is needed.

az login
az account list --output table
az account set --subscription "<your subscription name or ID>"
az account show --query "{name:name, id:id}" --output table
  1. Sign in with the account that can access the subscription.
  2. In VS Code, click the Accounts icon and sign in to Microsoft Foundry if prompted.
  3. Confirm the final command shows the subscription you intend to use.
05

Create a Microsoft Foundry project

This cloud project will hold your model and hosted workflow.

  1. Press Ctrl+Shift+P and run Foundry Toolkit: Create Project.
  2. Select your Azure subscription.
  3. Create a dedicated resource group such as rg-construct-agent-lab.
  4. Select a region the wizard shows as supporting Hosted Agents and your model.
  5. Enter a project name such as construct-career-lab.
  6. Wait until the project appears under My Resources in the Toolkit sidebar.
Permission check: Project creation normally requires Owner-level permission on the resource group. If blocked, ask the subscription owner to create the project or grant the required role.
06

Deploy a chat model

All four agents share one model deployment.

  1. Run Foundry Toolkit: Open Model Catalog.
  2. Select a small chat-capable model available in your project and region. A mini model is usually best for workshop speed and cost.
  3. Click Deploy, choose your project, and use an option with available quota.
  4. Wait for status Succeeded.
  5. Write down the exact deployment name.

The repo uses gpt-4.1-mini as an example. Do not force that name if it is unavailable; use the exact deployment name shown in your project.

07

Verify your Foundry permissions

Azure Contributor alone does not grant the data permissions needed to build agents.

  1. Open the Foundry resource in the Azure portal.
  2. Open Access control (IAM) → View my access.
  3. For local development, confirm Foundry User or higher.
  4. For hosted deployment, confirm Foundry Project Manager or Foundry Owner.
  5. Allow a few minutes for new role assignments to propagate.
Renamed roles: Some screens may still show Azure AI User, Azure AI Project Manager, or Azure AI Owner. Their role IDs and core permissions are unchanged.
08

Create the Python environment

Run these commands from the PersonalCareerCopilot folder.

python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements.txt

Your prompt should begin with (.venv). Verify the packages:

pip list | Select-String "agent-framework|mcp|debugpy"
PowerShell blocks Activate.ps1
Run Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass, then activate again. This changes policy only for the current terminal.
09

Create the local .env file

This connects the local workflow to your Foundry project and model.

  1. Create .env beside main.py.
  2. In the Toolkit sidebar, right-click your project and choose Copy Project Endpoint.
  3. Add the endpoint and exact deployment name:
FOUNDRY_PROJECT_ENDPOINT=https://<account>.services.ai.azure.com/api/projects/<project>
AZURE_AI_MODEL_DEPLOYMENT_NAME=<your exact deployment name>
Do not commit .env: Never paste Azure keys or passwords into this project. This lab uses your Microsoft Entra sign-in.
10

Review the workflow code

You do not need to rewrite it, but confirm these parts in main.py.

  • Four instruction constants
  • Four agents share one FoundryChatClient
  • Four executors use last_agent context
  • GapAnalyzer has the Learn MCP tool
  • Three edges form one straight chain
  • ResponsesHostServer starts the workflow
ResumeParser → JobDescriptionAgent → MatchingAgent → GapAnalyzer

Do not add a shortcut edge from ResumeParser to MatchingAgent. It can make the response run twice.

11

Run and test locally

Always pass the local test before deploying.

  1. Press F5 and select Debug Local Agent HTTP Server, or run Tasks: Run Task → Run Agent HTTP Server.
  2. Wait for the server on http://localhost:8088.
  3. Run Foundry Toolkit: Open Agent Inspector.
  4. Paste this sample and select Send:
Resume:
Jane Doe
Senior Software Engineer with 5 years of Python, Django, and AWS experience.
Built microservices and led a team of 4 developers.
Certification: AWS Solutions Architect Associate.

Job Description:
Senior Cloud Engineer.
Required: Python, Azure, Kubernetes, Terraform, and CI/CD.
Preferred: Go, Prometheus, Grafana, and cost optimization.
Experience: 5+ years in cloud infrastructure.
Certification: Azure Solutions Architect Expert preferred.

Pass conditions

  • Fit score out of 100
  • Matched and missing skills
  • One card for each important gap
  • Microsoft Learn URLs
  • No Python stack trace
  • One response, not a duplicate
12

Deploy the hosted workflow

Foundry deploys the four-agent workflow as one hosted agent.

  1. Stop the local test with Shift+F5 after it passes.
  2. Run Foundry Toolkit: Deploy Hosted Agent.
  3. Select the same project and the PersonalCareerCopilot source.
  4. If asked, choose Code deployment and Remote package mode. This avoids requiring local Docker.
  5. Review the model variable and chargeable resources.
  6. Select Deploy and wait for Active, Started, or Running.

The first deployment can take several minutes. Do not restart it while its status is Creating unless the logs show an error.

13

Verify in the hosted Playground

A local success does not prove cloud identity and settings are correct.

  1. Expand Hosted Agents in the Toolkit sidebar.
  2. Select your agent and active version.
  3. Open Playground.
  4. Send the same sample again.
  5. Compare structure, not exact wording.
CheckPass condition
CoordinationFit score and roadmap are both present.
ScoringThe score uses a 100-point evidence-based breakdown.
MCPGap cards contain learn.microsoft.com links.
HealthNo empty response, HTTP 500, authorization error, or timeout.

15

Fix common problems

Read the complete error before changing anything.

python or az is not recognized
Restart VS Code after installation. For Python, reinstall it with Add Python to PATH selected.
ModuleNotFoundError: agent_framework
Activate .venv and run pip install -r requirements.txt again.
FOUNDRY_PROJECT_ENDPOINT is missing
Put .env beside main.py and spell both variable names exactly as shown in Step 9.
403 Forbidden or AuthorizationFailed
Verify Foundry User for development and Foundry Project Manager or higher for deployment. Wait after a new role assignment, then sign in again.
Model or deployment not found
Use the exact deployment name from your project's Models or Deployments view.
No Microsoft Learn links
Confirm internet access to https://learn.microsoft.com/api/mcp.
The response appears twice
Keep only the three sequential edges. Remove any shortcut or fan-in edge.
Port 8088 is already in use
Stop the previous agent with Shift+F5 or close its terminal, then retry.
16

Finish and clean up safely

Model usage and hosted runtime sessions can generate Azure charges.

  • Local sample passed
  • Hosted sample passed
  • Fit score and roadmap present
  • Microsoft Learn links present
  • No real personal resume uploaded
  • Unused resources reviewed
Before deleting: Confirm the resource group contains only workshop resources. Deleting it permanently removes everything inside.
